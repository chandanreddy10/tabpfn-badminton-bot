# Experiments

The report is **[REPORT.md](REPORT.md)**. Everything here uses the game's own simulator and the bot's own feature
builder (they load `web/badminton.html` in Node), so every row is exactly what the bot sends TabPFN-3.5 in play.

| Folder / file | What it is |
|---|---|
| `adaptation/` | Main study, "one model, many worlds": X1 shuttle worlds, X2 world switches, X3 opponent habits, X5 uncertainty |
| `physics_comparison/` | An earlier, unfinished study comparing TabPFN-3.5 with physics models (not part of the report) |
| `common.py` | Cached TabPFN-3.5 wrapper (local weights), gradient boosting / random forest / kNN / ridge baselines, metrics |
| `figures/` | Figures used in the report (`x*` = adaptation, `e*` = physics comparison) |
| `results/` | Summary numbers behind the report (`adapt_summary.json`, `summary.json`) |

## Reproduce (from the repository root)

```
node experiments/adaptation/gen_adapt.js --seeds 2
.venv/bin/python experiments/adaptation/run_adapt.py --device mps --n-estimators 4   # ~27 min on an Apple M3
.venv/bin/python experiments/adaptation/analyze_adapt.py
```

The earlier physics comparison (long; I stopped it partway):

```
node experiments/physics_comparison/gen_data.js --seeds 3
.venv/bin/python experiments/physics_comparison/run_experiments.py --part all --device mps --n-estimators 4
.venv/bin/python experiments/physics_comparison/analyze.py
```

- Use `--device cpu` or `--device cuda` on other machines.
- Every TabPFN answer is cached in `experiments/cache/` (keyed by model, ensemble size and data), so an interrupted
  run continues where it stopped, and a rerun with unchanged data makes no TabPFN calls.
- Not committed (regenerated by the commands above): `data/`, `data_adapt/`, `cache/`, `logs/` and the per-point
  results `results/*.csv.gz`.
